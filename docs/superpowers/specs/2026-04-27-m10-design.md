# M10 — Phase 1 polish + offline + carattere axis

**Date:** 2026-04-27
**Status:** Approved (for now), awaiting spec review
**Owner:** Ali (product) / Claude (implementation)

## Context

Studiolo is a Next.js 16 + TypeScript port of an HTML prototype for a typographically-opinionated Italian SRS app. M1–M9 of the port are complete: 5 views, SRS module + tests, Coda errata hero, Studiare quiz with chained children, Aggiungi with auto-detect contenteditable, Dettatura with visibility-aware flash timing, Statistiche concordance with Italian collation. 116 tests, all green; tsc clean.

M10 is the wrap-up that turns the in-progress port into a shippable Phase 1: it wires the last live behaviors (ambient warmth, global Esc-to-Coda, prefers-color-scheme listener), implements real export/import, replaces the dead `voce` chip row with a working `carattere` (typeface) axis offering two distinct font sets, and adds a static-export + PWA layer so the app is installable and offline-capable.

The bet: the existing architecture (pure SRS module, Zustand stores, no API calls, all state in localStorage) makes a PWA layer trivial — it's mostly cache-the-app-shell and call it done.

## §2 — Export / Import flow

### Export

```
1. User clicks Esporta (Aspetto BackupGroup) OR AlarmBanner Esporta button
2. exportJson() reads full deck state via useDeckStore.getState()
3. Builds envelope: { version: 1, exportedAt: <ISO>, deck: { cards, errors, sessions, streakLastDay, streakCount, lastBackup } }
4. Triggers a synthetic <a download> with filename `studiolo-YYYY-MM-DD.json`
5. Calls useDeckStore.markBackedUp() — sets lastBackup = Date.now()
6. AlarmBanner re-renders with backup-not-overdue state (banner disappears)
7. BackupGroup shows "esportato · N carte" feedback for 2 seconds
```

### Import

```
1. User clicks Importa (Aspetto BackupGroup)
2. Hidden <input type="file" accept=".json"> fires click
3. On change: read file via FileReader, parse JSON
4. importJson.validate(parsed) returns { ok: true, preview, normalized } or { ok: false, error }
5. If invalid: BackupGroup shows error in alarm-red ("file non riconosciuto")
6. If valid: ImportPreviewModal opens showing:
     "Trovate 47 carte e 23 errori.
      Ultima esportazione: 12 aprile 2026.
      Cosa fare?"
   Three buttons: Sostituisci · Aggiungi · Annulla
7. Sostituisci → useDeckStore.importState(normalized) — replaces entire state
8. Aggiungi → useDeckStore.mergeState(normalized) — dedupe cards by id, append errors
9. Annulla → close modal, no state change
10. On Sostituisci/Aggiungi: modal closes, BackupGroup shows "importato · N carte" feedback
```

### File format

Envelope (v1, what we write):
```json
{
  "version": 1,
  "exportedAt": "2026-04-27T18:32:11.000Z",
  "deck": {
    "cards": [/* Card[] */],
    "errors": [/* ErrorEvent[] */],
    "sessions": [/* Session[] */],
    "streakLastDay": "2026-4-27",
    "streakCount": 1,
    "lastBackup": 1777309856890
  }
}
```

Backwards compat: prototype exports lacked the envelope. The validator detects shape and auto-wraps:
- If JSON has top-level `deck` → treat as v1
- If JSON has top-level `cards` (no `deck`) → wrap as v0 → upgrade to v1
- Otherwise → invalid

### Merge semantics (`mergeState`)

- **Cards:** existing wins on id collision; new cards get appended
- **Errors:** all errors appended chronologically (sorted by `when`)
- **Sessions:** all appended
- **Streak:** keep MAX(local, imported)
- **lastBackup:** set to `Date.now()` (the merge act counts as a sync)

### TDD coverage

- `exportJson.test.ts`: builds correct envelope, generates correct filename, returns timestamp
- `importJson.test.ts`: accepts v1, accepts v0 (prototype), rejects garbage, rejects missing fields, validates Card shape

## §3 — PWA layer (hand-rolled)

### Why hand-rolled, not `next-pwa`

- Studiolo has zero API calls, zero server-side dynamics, all state in localStorage
- Cache strategy is one paragraph: cache the app shell, serve from cache, fall through to network for updates
- `next-pwa` adds ~4MB + a build plugin + Next-version-specific config quirks for ~30 lines of work we can write ourselves
- Hand-rolled gives us exact control over what gets cached and the SW upgrade flow

### Manifest (`app/manifest.ts`)

Next 16 typed export. Theme color = `--accent` navy. Background = `--cream`. `display: "standalone"`, `orientation: "portrait"`, `lang: "it"`.

### Service worker (`public/sw.js`)

Stale-while-revalidate. Roughly:
- `install`: pre-cache `/`, `/manifest.webmanifest`, the favicon
- `activate`: delete old caches by name prefix, claim clients
- `fetch`: GET only; cache.match → fall through to network → put copy in cache; offline = cached response

About 50 lines, no dependencies, vanilla JS (so it can run in the SW context without bundling).

### Registration

`ClientShell` registers the SW on mount, **production only** (`process.env.NODE_ENV === "production"`). Skipping in dev avoids the classic "stale dev bundle cached, what changed??" trap.

### Icons

Typographic, brand-aligned. Built once and committed to `public/`:

| Asset | Size | Purpose |
|---|---|---|
| `favicon.svg` | scalable | tab favicon |
| `icon-192.png` | 192×192 | PWA install (small) |
| `icon-512.png` | 512×512 | PWA install (large) |
| `icon-maskable.png` | 512×512 with 10% safe-zone padding | Android adaptive icons |

Source SVG renders the wordmark `s.` in italic Iowan/Palatino, ink `#1a1612` on cream `#f5f1e8`, with the `.` in alarm `#8b2920`. `scripts/build-icons.mjs` uses `sharp` to render PNGs from the SVG and saves them to `public/`. Runs as a `prebuild` script.

### Install affordance

- `InstallPrompt` component captures `beforeinstallprompt` event, stashes the prompt, sets a state flag
- BackupGroup's third button (`Installa app`) is shown only when the flag is set
- Click triggers `prompt.prompt()` and clears the stashed event

iOS Safari doesn't fire `beforeinstallprompt`, so on iOS the button is hidden and we rely on the user using Share → Add to Home Screen. (We can add an instructional row in BackupGroup for iOS detection — defer unless time permits.)

## §4 — Static export config

`next.config.ts`:
```ts
const nextConfig: NextConfig = {
  output: "export",
  images: { unoptimized: true },
};
```

`npm run build` writes `out/`. Three usage paths:
1. Copy `out/` to any static host (Netlify, Vercel, GitHub Pages, S3 + CloudFront)
2. `npx serve out` for local HTTP (PWA registers, full offline works)
3. Open `out/index.html` directly via `file://` (PWA registration fails on `file://`, but localStorage and the app itself work)

Compatibility checklist (we already meet all of these):
- ✓ No server actions
- ✓ No `revalidate`
- ✓ All routes are static (no dynamic params)
- ✓ No `<Image>` usage (we use system fonts and CSS-only graphics)
- ✓ No API routes

## §5 — Plan-spec wiring

### `useAmbientWarmth`

```ts
useEffect(() => {
  function apply() {
    document.documentElement.style.setProperty(
      "--warm",
      String(currentWarm(new Date().getHours())),
    );
  }
  apply();
  const id = window.setInterval(apply, 10 * 60 * 1000);
  return () => window.clearInterval(id);
}, []);
```

Mounted in `ClientShell`. Doesn't depend on hydration — `currentWarm` is pure and the `--warm` token is just a CSS hint.

### `useEscToCoda`

Centralized in `ClientShell`. Smart behavior:

- If active element is a contenteditable / input / textarea AND has content → blur first (don't navigate)
- Otherwise → `router.push("/")`

Removes the per-view local Esc handlers in StudiareView and DettaturaView (which become redundant).

### `prefers-color-scheme` listener

Already in `ClientShell` for the Auto theme path. Verify it actually fires when the OS preference changes (DevTools → Rendering → Emulate prefers-color-scheme).

## §7 — Carattere axis (font picker, replaces former `voce` row)

The Aspetto panel's `voce` chip row gets renamed to `carattere` and offers two complete font sets. Each set is internally consistent (same serif everywhere it's used), and the two sets are visibly distinct from each other. Implemented via a single CSS variable swap so the entire app flips in lockstep — no per-element overrides needed.

### The two sets

**`antica`** (default — the current font system; warm humanist, old-printed-book feel):
```css
--serif-antica: 'Iowan Old Style', 'Charter', 'Palatino Linotype', 'Book Antiqua', Palatino, Georgia, 'Times New Roman', serif;
```
- Renders Iowan on macOS/iOS, Palatino Linotype on Windows, Georgia as last resort
- The current default — already the look of M1–M9

**`moderna`** (high-contrast Italian publishing tradition — Bodoni-style; think Adelphi / Einaudi covers):
```css
--serif-moderna: 'Bodoni 72', 'Bodoni Linotype', 'Big Caslon', Cambria, Constantia, Georgia, 'Times New Roman', serif;
```
- Renders Bodoni 72 on macOS, Bodoni Linotype on Windows (with Office), Cambria/Constantia on Windows otherwise, Georgia as last resort
- High thick/thin contrast — a more dramatic, formal voice

### Mono stack

Mono stays shared between sets. Mono is chrome (running-head, section labels, chip labels, counters) — swapping it would be over-design and make the two sets feel arbitrary instead of intentional.

### Implementation

```css
:root {
  --serif-antica: /* ... */;
  --serif-moderna: /* ... */;
  --serif: var(--serif-antica); /* default */
  --mono: ui-monospace, 'SF Mono', Menlo, 'Cascadia Mono', Consolas, monospace;
}
html[data-carattere="moderna"] {
  --serif: var(--serif-moderna);
}
```

Every existing `var(--serif)` reference (body, wordmark, errata, quiz-question, ToC, etc.) automatically swaps. No additional CSS rules per element.

### Store + types changes

In `lib/store/ui.ts`:
- Rename type `Voice` → `Carattere`, values `tipografo|manoscritto` → `antica|moderna`
- Rename field `voice` → `carattere` (with default `'antica'`)
- Rename action `setVoice` → `setCarattere`
- Persistence key bump: `studiolo.ui.v1` → `studiolo.ui.v2`, with a `migrate` function in the persist config that drops any legacy `voice` field and seeds `carattere: 'antica'`

In `app/layout.tsx`:
- Replace `data-voice="manoscritto"` with `data-carattere="antica"` on `<html>`

In `components/shell/ClientShell.tsx`:
- Apply `root.dataset.carattere = carattere` instead of `root.dataset.voice = voice`

In `components/shell/TweaksPanel.tsx`:
- Replace `VOICES` array with `CARATTERI = [{v:'antica', label:'antica'}, {v:'moderna', label:'moderna'}]`
- Section label renames `voce` → `carattere`

The `ThemeToggle` file (now unused since theme moved to Aspetto) can be deleted to keep the tree clean.

### Verification

- Toggle Aspetto → carattere → moderna. Body text + wordmark + errata corrections + quiz question all switch to Bodoni-style.
- Toggle back to antica. All elements return to Iowan/Palatino.
- Mono chrome (running-head, section labels, chips) stays in mono — unchanged in both modes.
- Persistence: reload the page after switching; carattere choice survives.

### Why this design

- **One source of truth.** Only `--serif` changes between sets. No per-element overrides means no "we forgot to swap that one element" bugs.
- **Both sets are themselves consistent.** Within `antica`, every serif use renders Iowan. Within `moderna`, every serif use renders Bodoni-style. The user said "keep the font 1 and consistent" — this delivers that within each set.
- **Two distinctly-different options.** Like day/night for `--theme`, antica/moderna are two visibly different choices for `--serif`. Same architectural pattern.
